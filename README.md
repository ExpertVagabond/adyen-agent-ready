# adyen-agent-ready

An agent-legibility audit of Adyen's developer surfaces, plus an MCP server for the Adyen TEST environment that fills the gaps the audit found.

Adyen's Developer Relations team describes its mission as making Adyen "the easiest platform to integrate with, for humans and agents alike" and treating "agent-legible and agent-reliable" developer surfaces as an explicit quality bar. This repo measures that bar against the live surfaces: `docs.adyen.com/llms.txt`, `llms-full.txt`, every `.md` page, `robots.txt`, the OpenAPI specs in `Adyen/adyen-openapi`, and the official `@adyen/mcp` server.

**Read the result: [AUDIT.md](./AUDIT.md)** (17 numbered findings, each with URLs and measured evidence, regenerated by `npm run audit`).

## What the audit found (2026-09-14)

| # | Finding | Measured |
|---|---|---|
| 1 | docs.adyen.com serves a Cloudflare JavaScript challenge to a plain HTTP client | HTTP 429 + `cf-mitigated: challenge` on `.md` URLs after ~1,000 fetches; no `Retry-After` |
| 2 | `llms-full.txt` is larger than any model context | 51.1 MB, about 13.4M tokens |
| 3 | The API reference is not in `llms.txt` | 0 of 2,524 entries; guides link to the JS-only API Explorer 11,370 times |
| 4 | Docs mix Checkout API versions | 245 pages use two or more versions in their own examples; spec and SDK are at v72 |
| 5 | Snippets that do not parse | 847 of 7,870 JSON/JS/TS/Python blocks fail even as fragments; 526 more need dedent or wrapping |
| 6 | Docs-template markup leaks into Markdown | `{hint:...}{/hint}` on 115 pages, 66 times inside JSON examples |
| 7 | Stale pages | 801 of 2,523 pages declare `last_modified` more than 3 years ago |

Plus: 6 pages over 100k tokens each (every language tab inlined), 270 unlabelled code fences, 57,539 site-relative links, 42 pages in the sitemap but not in `llms.txt`, and the official MCP covering 8 of 29 Checkout operations (no `/payments`, no `/payments/details`). The one thing that is right: `robots.txt` explicitly allows six named AI crawlers, and every page has a `.md` twin with `last_modified` in its frontmatter. The posture is right; the content is the gap.

## The MCP server

Eight tools. The three that need credentials talk to `checkout-test.adyen.com/v72` through the official Node SDK; the rest work offline.

| Tool | What it does |
|---|---|
| `adyen_list_payment_methods` | POST `/paymentMethods` |
| `adyen_create_session` | POST `/sessions` (Sessions flow); returns `id` and `sessionData` for Drop-in |
| `adyen_get_session` | GET `/sessions/{id}` |
| `adyen_create_payment` | POST `/payments` with a raw test card (Advanced flow, TEST only) |
| `adyen_submit_payment_details` | POST `/payments/details` after a redirect or 3DS action |
| `adyen_test_cards` | Filter the 92-card test catalogue by brand, country, 3DS2 |
| `adyen_docs_lookup` | Search `llms.txt` and fetch the best page as Markdown, trimmed to a token budget; explains a Cloudflare challenge instead of returning HTML |
| `adyen_audit_findings` | Read the audit findings (summary, by severity, or by id) |

Credentials come from the environment only; no tool argument ever carries a key.

```jsonc
// Claude Desktop / Cursor / VS Code
{
  "mcpServers": {
    "adyen-agent-ready": {
      "command": "npx",
      "args": ["-y", "github:ExpertVagabond/adyen-agent-ready"],
      "env": { "ADYEN_API_KEY": "${ADYEN_API_KEY}", "ADYEN_MERCHANT_ACCOUNT": "${ADYEN_MERCHANT_ACCOUNT}" }

  }

```

Or from a checkout: `npm install && npm run build && node dist/mcp/server.js`.

### Getting a free Adyen test account

1. Sign up at https://www.adyen.com/signup (a test Customer Area, no contract).
2. In the Customer Area go to **Developers > API credentials**, create a **web service user**, and generate an **API key**. Give it the *Checkout webservice role*; add *API PCI Payments role* if you want `adyen_create_payment` to accept raw test-card numbers.
3. Note your merchant account code from **Account > Merchant accounts**.
4. `export ADYEN_API_KEY=... ADYEN_MERCHANT_ACCOUNT=...` then `npm run smoke`.

`ADYEN_ENVIRONMENT=LIVE` is refused unless `ADYEN_ALLOW_LIVE=1` and `ADYEN_LIVE_PREFIX` are also set.

## Running the audit

```
npm install
npm run audit            # fetch live surfaces (polite: 3 workers, 400 ms delay, backoff on 429), ~6 min
npm run audit:offline    # re-analyse from .cache/ without the network, ~6 s
npm test                 # 31 unit tests
npm run typecheck
```

The crawler identifies itself (`adyen-agent-ready-audit/0.1 (+repo URL)`), caches every response under `.cache/`, retries 429/503 with 30/60/120 s backoff, and records each run in `audit/crawl-runs.json`. The first run at concurrency 12 is what produced finding 1.

### Method, in one paragraph

Parse `llms.txt` and `sitemap.xml` and diff them. Fetch every `.md` URL `llms.txt` advertises; record status, content type, redirects, `Last-Modified` and `ETag`. Parse each page for frontmatter, fenced code blocks (with language tags and the prose that precedes them), links, Checkout endpoint versions and API Explorer links. Lint JSON with `JSON.parse`, JS/TS with the TypeScript parser, Python with `ast.parse`, counting a block as usable if it parses as a fragment after dedent or wrapping. Load the latest `CheckoutService-v*.json`, map API Explorer links to operations, and validate request examples against the request schema of the endpoint their prose links to (top-level fields, conservative attribution). Parse the official `adyen-mcp` README and diff it against the spec. Read `robots.txt` for named AI agents. Limitations are listed at the end of `AUDIT.md`.

## `data/llms-checkout.txt`

Finding 3 says the API reference is unreachable to agents. This file is the fix in miniature: one Markdown block per Checkout v72 operation, generated from the OpenAPI document, required fields first, optional fields listed, a link back to the API Explorer. It is what a `## API reference` section of `llms.txt` would point at.
